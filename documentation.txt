1. PROJECT OVERVIEW
================================================================================

EcoBeacon AI is a full-stack web application for personal carbon footprint
tracking and reduction. Users log daily activities across four categories
(transportation, electricity, food, shopping), receive precise CO2 emission
calculations, and get AI-powered recommendations to reduce their environmental
impact.

Key Features:
  - Activity logging with real-time emission preview
  - Natural language activity parser ("I drove 20km to work")
  - GPS-based automatic trip tracker with transport mode detection
  - Personalized AI recommendations, 7-day emission forecast, anomaly detection
  - Eco Score (0-100) with streak tracking and achievement badges
  - Interactive dashboard: charts, category breakdowns, forecasts
  - Rule-based AI chat assistant
  - Impact context (equivalencies: trees, phone charges, showers, etc.)

6. DATABASE
================================================================================

Engine: SQLite (file at backend/data/ecobeacon.sqlite)
ORM:    Sequelize 6

Tables are auto-created via sequelize.sync() on server startup. No migrations
are required. The data directory is created automatically if it doesn't exist.

Users Table
-----------
Column          | Type     | Notes
----------------+----------+----------------------------------------------
id              | INTEGER  | Auto-increment primary key
name            | STRING   | Max 50 chars, required
email           | STRING   | Unique, required, stored lowercase
password        | STRING   | bcrypt hash (12 rounds)
ecoScore        | FLOAT    | 0–100, default 50
totalEmission   | FLOAT    | Cumulative kg CO2, default 0
badges          | TEXT     | JSON-serialized array of badge objects
streak          | INTEGER  | Consecutive days logged, default 0
lastLogDate     | DATE     | Date of last logged activity
createdAt       | DATE     | Auto-managed by Sequelize
updatedAt       | DATE     | Auto-managed by Sequelize

Activities Table
----------------
Column          | Type     | Notes
----------------+----------+----------------------------------------------
id              | INTEGER  | Auto-increment primary key
userId          | INTEGER  | References users.id (no FK constraint)
type            | STRING   | One of: transportation, electricity, food, shopping
category        | STRING   | e.g., car, bus, beef, solar, secondhand
value           | FLOAT    | Quantity (km, kWh, meals, items)
unit            | STRING   | Display unit, default ''
emission        | FLOAT    | Pre-calculated kg CO2
notes           | STRING   | Optional, max 200 chars
date            | DATE     | Defaults to now
createdAt       | DATE     | Auto-managed
updatedAt       | DATE     | Auto-managed

Both models expose a virtual _id field (alias for id) for frontend compatibility.

7. BACKEND ARCHITECTURE
================================================================================

7.1 ENTRY POINT — backend/server.js
------------------------------------
The startServer() async function:
  1. Calls connectDB() — authenticates SQLite, syncs Sequelize models
  2. Creates Express app with:
       - CORS (allowed origin: CLIENT_URL env var)
       - JSON body parsing (10 MB limit)
       - URL-encoded body parsing
  3. Mounts routes:
       /api/auth        → authRoutes
       /api/activity    → activityRoutes
       /api/emissions   → emissionRoutes
       /api/ai          → aiRoutes
  4. Health check: GET /api/health → { status: 'OK', timestamp }
  5. 404 handler and global error handler
  6. Listens on PORT (default 5000)

7.2 CONFIGURATION
-----------------
backend/config/sequelize.js
  Creates the Sequelize instance using SQLite dialect.
  Stores the database at backend/data/ecobeacon.sqlite.
  Ensures the data/ directory exists using fs.mkdirSync.

backend/config/db.js
  Calls sequelize.authenticate() to verify the connection.
  Requires both model files (so Sequelize registers them).
  Calls sequelize.sync() to create/update tables.
  Calls process.exit(1) on failure.

7.3 MODELS
----------
backend/models/User.js
  Sequelize model. Notable details:
  - password is never returned in API responses (excluded in queries)
  - badges field uses a custom getter (JSON.parse) and setter (JSON.stringify)
    so the controller always works with a plain JS array
  - _id virtual field returns this.id for MongoDB-style frontend compatibility

backend/models/Activity.js
  Sequelize model.
  - type is validated against the enum: [transportation, electricity, food, shopping]
  - emission is stored at creation and is not recalculated on read
  - _id virtual field returns this.id

7.4 MIDDLEWARE
--------------
backend/middleware/authMiddleware.js — exports protect()

  Steps:
    1. Read Authorization header, extract Bearer token
    2. Return 401 if no token
    3. Verify token with jwt.verify(token, JWT_SECRET)
    4. Find user by decoded.id, excluding the password field
    5. Return 401 if user not found or token invalid
    6. Attach user to req.user and call next()

7.5 ROUTES
----------
Auth Routes (backend/routes/authRoutes.js)
  POST   /api/auth/register    → register (public)
  POST   /api/auth/login       → login (public)
  GET    /api/auth/profile     → getProfile (protected)
  PUT    /api/auth/profile     → updateProfile (protected)

Activity Routes (backend/routes/activityRoutes.js)
  POST   /api/activity/add          → addActivity (protected)
  GET    /api/activity/user/:id     → getUserActivities (protected)
  DELETE /api/activity/:id          → deleteActivity (protected)

Emission Routes (backend/routes/emissionRoutes.js)
  GET    /api/emissions/summary/:id → getEmissionSummary (protected)

AI Routes (backend/routes/aiRoutes.js)
  GET    /api/ai/suggestions/:userId → getSuggestions (protected)
  GET    /api/ai/forecast/:userId    → getForecast (protected)
  GET    /api/ai/anomalies/:userId   → getAnomalies (protected)
  POST   /api/ai/chat                → chatResponse (protected)

7.6 CONTROLLERS
---------------
authController.js
  register(req, res)
    - Validates: name, email, password all present
    - Checks for duplicate email (returns 400 if taken)
    - Hashes password: bcrypt.hash(password, 12)
    - Creates user with ecoScore=50, streak=0, badges=[]
    - Signs JWT with 30-day expiry
    - Returns: { user: {...}, token }

  login(req, res)
    - Finds user by email (lowercase)
    - Compares password with bcrypt.compare
    - Signs JWT, returns { user: {...}, token }

  getProfile(req, res)
    - Returns req.user (already fetched by authMiddleware)

  updateProfile(req, res)
    - Only accepts name updates currently
    - Updates and returns the refreshed user

activityController.js
  addActivity(req, res)
    - Validates type, category, value (value must be > 0)
    - Calls calculateEmission(type, category, value) from emissionService
    - Creates Activity record
    - Fetches all user activities to recalculate stats
    - Calls calculateEcoScore, getBadges, updateStreak from ecoScore utils
    - Updates User record (ecoScore, totalEmission, badges, streak, lastLogDate)
    - Returns: { activity, ecoScore, totalEmission, streak, badges }

  getUserActivities(req, res)
    - Authorization: req.user.id must match req.params.id
    - Query params: page (default 1), limit (default 20), type, startDate, endDate
    - Returns: { activities, pagination: { total, page, pages } }

  deleteActivity(req, res)
    - Deletes activity by id
    - Recalculates and saves new ecoScore and totalEmission for the user
    - Returns: { message, ecoScore, totalEmission }

emissionController.js
  getEmissionSummary(req, res)
    - Authorization check: user can only fetch their own summary
    - Runs 4 parallel queries: today / last 7 days / current month / all time
    - Returns:
        summary:            { daily, weekly, monthly, total } in kg CO2
        dailyBreakdown:     7-day array, each with total + per-type breakdown
        monthlyBreakdown:   30-day array (same shape)
        categoryBreakdown:  per-type totals with percentage (current month)
        activityCount:      { today, week, month, total }

aiController.js
  getSuggestions(req, res)
    - Fetches activities from the last 30 days
    - Calls generateRecommendations(activities, ecoScore)
    - Returns up to 6 suggestions

  getForecast(req, res)
    - Fetches activities from the last 30 days
    - Calls forecastEmissions(activities, 7) and generateWeeklyGoals(activities, ecoScore)
    - Returns: { forecast: [...], goals: [...] }

  getAnomalies(req, res)
    - Fetches activities from the last 30 days
    - Calls detectAnomalies(activities)
    - Returns: { anomalies: [...] }

  chatResponse(req, res)
    - Regex-based keyword dispatcher on req.body.message
    - No activity data used; returns pre-written string responses
    - See Section 9.5 for full keyword mapping

7.7 SERVICES
------------
backend/services/emissionService.js
  EMISSION_FACTORS: hardcoded lookup table (see Section 10 for full table)

  calculateEmission(type, category, value)
    - Looks up the factor for type+category
    - Returns +(factor * value).toFixed(4) as a float
    - Returns 0 if type or category is not found

backend/services/aiService.js
  See Section 9 for the full AI engine documentation.

7.8 UTILITIES
-------------
backend/utils/ecoScore.js

  calculateEcoScore(activities)
    - Computes daily average emission across unique logged days
    - Maps average to a base score:
        ≤ 2 kg/day  → 95    ≤ 4 → 88    ≤ 6 → 78    ≤ 8 → 68
        ≤ 12 → 56   ≤ 16 → 44  ≤ 20 → 33  ≤ 25 → 22  ≤ 30 → 15
        > 30 → 10
    - Adds consistency bonus (0–10 points): proportion of eco-friendly activities
      (walking, bike, train, veg/vegan meals, eco-friendly/secondhand shopping)
    - Clamps final score to 0–100

  getScoreLabel(score)
    - score ≥ 80 → "Excellent"
    - score ≥ 50 → "Moderate"
    - else       → "Needs Improvement"

  getBadges(ecoScore, streak, totalActivities)
    - Activity count milestones: 1 (First Step), 10 (Getting Started), 50 (Eco Warrior)
    - Score thresholds:          60 (Green Thinker), 80 (Climate Hero), 90 (Eco Legend)
    - Streak milestones:         3 days (3-Day Streak), 7 days (Week Warrior),
                                 30 days (Monthly Master)

  updateStreak(user)
    - Compares lastLogDate to today (date only, no time)
    - Same day    → no change (already logged today)
    - Next day    → streak + 1
    - Gap ≥ 2 days → reset to 1 (streak broken)
    - Returns { streak, lastLogDate }

7.9 SEED DATA — backend/seed/seedData.js
-----------------------------------------
  - Calls sequelize.sync({ force: true }) — DROPS all tables first
  - Creates 3 demo users: alex, sam, jordan (all password: password123)
  - Creates 30 activities per user randomly sampled from 18 templates:
      car 20km, flight 1000km, bus 15km, train 50km, bike 10km,
      electric car 30km, standard electricity 5kWh, solar electricity 10kWh,
      beef meal, meat meal, veg meal, vegan meal, fish meal, fast food,
      high-impact shopping, normal shopping, eco-friendly shopping, secondhand
  - Activities are dated randomly across the past 30 days
  - Eco scores and badges are calculated and saved after all activities are created

8.2 ROUTING & ROUTE GUARDS — frontend/src/App.jsx
---------------------------------------------------
Wraps the entire app in <BrowserRouter> and <AuthProvider>.

ProtectedRoute component:
  - Shows fullscreen LoadingSpinner while AuthContext is initializing
  - Redirects to /login if user is null

PublicRoute component:
  - Redirects to /dashboard if user is already authenticated

Route table:
  /          → redirect to /dashboard
  /login     → <Login />     (PublicRoute)
  /register  → <Register />  (PublicRoute)
  /dashboard → <Dashboard /> (ProtectedRoute)
  /log       → <LogActivity />(ProtectedRoute)
  /profile   → <Profile />   (ProtectedRoute)
  *          → redirect to /dashboard

The <AIChat /> floating chatbot is rendered globally outside the Routes block
so it persists across page navigations. It is only shown when user is set.

8.3 AUTH CONTEXT — frontend/src/context/AuthContext.jsx
--------------------------------------------------------
Provides global auth state via React Context + useContext hook.

State:
  user     — authenticated user object or null
  token    — JWT string (initialized from localStorage 'eco_token' on mount)
  loading  — true while the initial profile fetch is in-flight

Methods:
  login(email, password)
    POST /auth/login → stores token in localStorage + sets user state

  register(name, email, password)
    POST /auth/register → same as login

  logout()
    Clears 'eco_token' from localStorage, sets user and token to null

  refreshUser()
    GET /auth/profile → updates user state
    Called after logging an activity so the navbar eco score reflects the change

On mount, if a token exists in localStorage, it calls GET /auth/profile to
restore the session. Sets loading = false when done.

8.4 API SERVICE — frontend/src/services/api.js
-----------------------------------------------
Axios instance configuration:
  baseURL:  '/api'      (proxied by Vite to http://localhost:5000)
  timeout:  10000ms

Request interceptor:
  Reads 'eco_token' from localStorage.
  If found: adds Authorization: Bearer <token> header.

Response interceptor (error handling):
  On 401: removes 'eco_token' from localStorage, redirects to /login.
  All other errors: re-thrown for the caller to handle.

    % of Paris Agreement target    (2.5 kg/day)
  Both bars are color-coded: green / amber / red.

    Weighted average of rolling speed window (recent readings weighted higher).
    Classification thresholds:
      < 1 km/h   → stationary
      < 7 km/h   → walking
      < 25 km/h  → cycling
      < 60 km/h  → bus / city driving
      < 130 km/h → car
      < 350 km/h → train
      ≥ 350 km/h → flight

  formatDistance(km) / formatSpeed(kmh)

frontend/src/hooks/useGeoTracker.js
  Custom hook wrapping navigator.geolocation.watchPosition.
  State machine: idle → requesting → tracking → stopped (or error)
  GPS jitter filter: only accumulates distance when movement > 5 meters.
  Rolling speed window of 8 readings for transport classifier.
  1-second interval timer for duration display.
  Exposed API:
    status, distanceKm, currentSpeedKmh, detectedMode, duration, errorMsg
    start(), stop(), reset()

9. AI / RECOMMENDATION ENGINE
================================================================================

All AI logic is in backend/services/aiService.js and the chat handler in
backend/controllers/aiController.js. No external ML library or API is used.
All logic is rule-based JavaScript operating on the user's last 30 days of data.

9.1 RECOMMENDATION GENERATOR — generateRecommendations(activities, ecoScore)
------------------------------------------------------------------------------
Groups activities by type using groupByType(), then applies rules:

Transportation Rules:
  ≥ 3 car trips      → "Switch to Public Transport" (HIGH)
                         saving = 60% of total car emissions
  Any flights        → "Reduce Air Travel" (HIGH)
                         saving = 80% of flight emissions
  No eco trips but
  ≥ 2 transport logs → "Try Walking or Cycling" (MEDIUM)

Electricity Rules:
  Total kWh > 15     → "Reduce Peak Hour Usage" (HIGH)
                         saving = 12% of electricity emissions
  Any electricity    → "Explore Renewable Energy" (MEDIUM)
                         saving = 90% of electricity emissions

Food Rules:
  meat count >
  veg count          → "Reduce Meat Consumption" (HIGH)
                         saving = 65% of meat emissions
  ≥ 3 fast food      → "Cook More at Home" (MEDIUM)
                         saving = 60% of fast food emissions

Shopping Rules:
  Any high-impact    → "Choose Eco-Friendly Products" (MEDIUM)
                         saving = 70% of high-impact emissions
  ≥ 3 normal items   → "Try Secondhand Shopping" (LOW)
                         saving = 80% of normal shopping emissions

Score-based Rules:
  ecoScore < 40      → prepends "Start Small — Big Impact" (HIGH)
  ecoScore ≥ 80      → appends "Inspire Your Community" (LOW)

Sorting & limit: sorted HIGH → MEDIUM → LOW, truncated to 6 suggestions.
No data: 3 default onboarding suggestions returned.

9.2 EMISSION FORECASTER — forecastEmissions(activities, days=7)
----------------------------------------------------------------
  1. Groups activities by date, builds a daily total map.
  2. Calculates overall mean daily emission.
  3. Splits day-series into two halves; computes average of each half.
  4. Linear trend delta = (second half avg - first half avg) per day.
  5. Generates N future date entries:
       predicted[i] = max(0, mean + trendDelta * i)
  6. Confidence:
       ≥ 14 data days → "high"
       ≥  7 data days → "medium"
       else           → "low"
  7. Trend label:
       delta > 0.1  → "increasing"
       delta < -0.1 → "decreasing"
       else         → "stable"
  Returns [] if no activity data exists.

9.3 ANOMALY DETECTOR — detectAnomalies(activities)
---------------------------------------------------
Requires ≥ 5 activities. For each activity type independently:
  1. Compute mean and standard deviation of emissions in that type.
  2. Flag any activity where:
       emission > mean + 2*stdDev   AND   emission > mean * 2
  3. Attach message: "This [category] trip was 4.2× your usual average"
Returns maximum 5 anomalies total.

9.4 WEEKLY GOAL GENERATOR — generateWeeklyGoals(activities, ecoScore)
----------------------------------------------------------------------
Car travel:
  Weekly avg km = total car km / 4
  Target = 80% of avg
  Saving = (avg - target) * 0.21 kg/km

Meat meals:
  Weekly avg count = total meat count / 4
  Target = max(0, avg - 1)  (reduce by one meal per week, capped at 3)
  Saving = 25% of weekly meat emissions

Electricity:
  Weekly avg kWh = total kWh / 4
  Target = 90% of avg
  Saving = (avg - target) * 0.85 kg/kWh

ecoScore < 60:
  Adds "Boost Eco Score by 10 Points" goal.

Returns maximum 3 goals.

12. ECO SCORE & GAMIFICATION
================================================================================

ECO SCORE (0–100)
-----------------
Base score derived from average daily emission (all-time):
  ≤ 2 kg/day  → 95    |   ≤ 12 → 56   |   ≤ 25 → 22
  ≤ 4         → 88    |   ≤ 16 → 44   |   ≤ 30 → 15
  ≤ 6         → 78    |   ≤ 20 → 33   |   > 30 → 10
  ≤ 8         → 68    |

Consistency bonus (0–10): proportion of eco-friendly activities:
  Eco-friendly types: walking, bike, train, veg/vegan meals,
                      eco-friendly and secondhand shopping

Final score = base + bonus, clamped to [0, 100].

Score labels:
  ≥ 80 → "Excellent"
  ≥ 50 → "Moderate"
  else → "Needs Improvement"

BADGES
------
Activity Count:
  1 activity   → "First Step"
  10 activities → "Getting Started"
  50 activities → "Eco Warrior"

Eco Score:
  score ≥ 60 → "Green Thinker"
  score ≥ 80 → "Climate Hero"
  score ≥ 90 → "Eco Legend"

Streak:
  3 days  → "3-Day Streak"
  7 days  → "Week Warrior"
  30 days → "Monthly Master"

STREAKS
-------
A streak is the number of consecutive calendar days on which at least one
activity has been logged.
  - Logging on the same day does not increment the streak.
  - Logging on the next calendar day increments streak by 1.
  - Any gap of ≥ 2 days resets the streak to 1.

13. KNOWN NOTES & DESIGN DECISIONS
================================================================================

SQLite over MongoDB
  Despite README.md and .env.example referencing MongoDB/Mongoose, the actual
  implementation uses SQLite + Sequelize. This makes the app zero-infrastructure
  — no database server is needed; the .sqlite file is created automatically.

_id Virtual Fields
  Both User and Activity models expose a _id virtual field aliasing the integer
  primary key. This allows frontend code written in a MongoDB-compatible style
  to work transparently with Sequelize integer PKs.

Duplicate Emission Factors
  EMISSION_FACTORS is defined in both backend/services/emissionService.js and
  frontend/src/utils/helpers.js. The backend is authoritative for stored values;
  the frontend copy enables live previews without an API roundtrip.

No External AI
  OPENAI_API_KEY appears in .env.example but is never consumed. All "AI" features
  (NLP parser, GPS classifier, forecasting, anomaly detection, chat) are built
  from scratch as rule-based JavaScript logic.

JWT in localStorage
  Token key: 'eco_token'. The Axios response interceptor automatically clears it
  and redirects to /login on any 401 response.

User Authorization Pattern
  Both activityController and emissionController explicitly check
  req.user.id === parseInt(req.params.id) before returning data. This prevents
  one authenticated user from accessing another user's data via URL manipulation.

Seed Script Warning
  seedData.js uses sequelize.sync({ force: true }), which drops and recreates
  all tables. Never run npm run seed on a database with real production data.
